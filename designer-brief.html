Guild Ranks · artwork brief

How each card gets its own code

You are not designing 675 cards. You are designing ten, each with one small placeholder that gets filled from a spreadsheet at output time.

It's a data merge

The same mechanism as personalised invitations or numbered event tickets. One master file per rank, one CSV, one merged output. Nobody places a code by hand, and no file is duplicated 250 times.

What you're delivering

Per rank, two print-ready files:

  • Front — the rank artwork. No variable content at all.
  • Back — the stamp grid, plus a reserved zone where the code goes.

Twenty files total. The code placeholder is the only thing that differs card to card. Only ranks 1–3 are needed for the first print run.

The code zone

RequirementSpec
QR size20 × 20 mm minimum at finished size. Bigger is fine.
Quiet zoneAt least 2 mm clear on all four sides. No artwork, rules or texture intruding.
ContrastDark modules on a light ground. Near-black on near-white is safest.
BackgroundFlat colour only. No gradient, photograph or paper texture behind the code.
Readable codeDirectly beneath the QR. 7 pt minimum, generous letter-spacing.
PositionOn the back, outside the stamp grid, with a visible divider or frame.

Do not invert the QR

Light modules on a dark ground fail on a meaningful share of phone scanners, and you only discover it after printing.

The rank artwork will want to be dark and moody. The code doesn't get to be. Give it a light panel and make that panel a deliberate part of the design — a parchment strip, an inset plate, a torn label. Something that reads as chosen rather than tolerated.

One thing that buys you freedom

The QR is scanned once, within about a minute of the card being handed over, and is dead weight for the rest of the card's life. It does not need to survive weeks of stamping, beer and wallet abrasion.

So put it in the least precious real estate on the back. It doesn't deserve prime position, and treating it as disposable furniture rather than a hero element will make the card look better. The readable code underneath is the part worth protecting — it stays useful for support lookups long after the QR is spent.

Two ways to get the codes on

Agree which with the printer before building files — it changes what you hand over.

Route A

The printer merges

You deliver flat artwork with the code zone left empty but clearly marked. Their RIP drops each code in as it prints. Ask for variable data printing — every trade digital printer does it. Expect a setup fee.

Hand over: artwork PDFs + for_printer/level_NN_*.csv

Route B · usually better

You merge

You run the merge in InDesign and export one flat multi-page PDF. The printer receives an ordinary job with no VDP surcharge, and you keep full control over placement.

Hand over: one merged PDF per rank

Running the merge in InDesign

Everything is in output/for_designer/. Each rank has a CSV with a folder of QR images beside it — paths are relative, so keep those two together.

  1. Open the card back file for that rank.
  2. Draw a graphic frame, exactly 20 × 20 mm, where the QR goes.
  3. Draw a text frame directly beneath it for the readable code.
  4. Window → Utilities → Data Merge.
  5. Panel menu → Select Data Source → level_01_..._indesign.csv.
  6. Drag the @qr field onto the graphic frame. The @ prefix is how InDesign knows those values are image paths rather than text — it's already in the file, don't rename the column.
  7. Drag card_code into the text frame.
  8. Panel menu → Create Merged Document.
  9. Export as PDF/X-1a or PDF/X-4, whichever the printer asks for.

Character set

Codes are six characters, always starting with a letter:

23456789ABCDEFGHJKMNPQRSTVWXYZ   I L O U 0 1

Those six are excluded so nothing gets misread when someone reads a code down the phone. Pick a face where the survivors stay distinct — particularly 5/S, 8/B and 2/Z. Monospaced or clearly-drawn geometric is safest; ornate display faces are not.

Things that go wrong

SymptomCause
Grey boxes instead of QRs The CSV and its image folder have been separated. They must stay side by side.
Blurry or cropped QRs Frame fitting is scaling the image. The PNGs are ~420 dpi at 20 mm, so anything soft means it's being resampled.
Broken image paths The CSV was opened and re-saved in Excel, which rewrites the path column. Use a plain text editor, or ask for a fresh file.
Wrong codes on the wrong rank The expensive one. Run each rank as a completely separate job, with only that rank's CSV and artwork open. Then there is nothing to misalign.

Before the full run

Print a proof and scan three cards from it with a cheap Android phone, in dim light. Bar lighting, not studio lighting.

Check each opens a form with the code already filled in, and that the code on screen matches the one printed on that card. Two minutes, and it catches every failure listed above.
