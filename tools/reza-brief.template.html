Guild Ranks · build brief

Set up the forms and the sheet

Roughly an hour of clicking, plus half an hour trying to break it. Everything you need is on this page — the script is here in full, and the card data comes as a CSV attached separately.

What this is

A loyalty scheme on physical cards. Each card carries a unique code as a QR on its back. When a member scans it, we check the code is real, unused, and exactly one rank above where they currently are — then promote them and burn the code so it can never be used again.

You're building the plumbing: one spreadsheet, two Google Forms, one script. Bar staff never type anything.

Step 1Spreadsheet and three tabs

New Google Sheet called Loyalty. Three tabs, named exactly:

Members · Cards · Activation log

Headers go in row 1. The script finds columns by name, so spelling and capitalisation matter — but order doesn't, and columns can be added later without breaking anything.

Members

Email │ Name │ Level │ Joined │ Last activated │ Consent

Cards

Card code │ Level │ Status │ Member email │ Activated at │ Batch

Activation log

Time │ Submitted code │ Submitted email │ Result │ Reason

Freeze row 1 on each (View → Freeze → 1 row). Set the Level column on Members to plain Number formatting — if it ends up as text, levels silently stop updating.

Step 2Import the cards

On the Cards tab: File → Import → Upload, choose the attached cards_import_2026-08-launch.csv.

Import location: Append to current sheet. Separator: detect automatically.

675 rows should land, every one showing unissued. The Member email and Activated at columns stay empty — the script fills those in.

Step 3Signup form

This one sits behind the QR on table standees. New form, called something like Join the Guild. Three questions, titled exactly as below — the script reads answers by question title.

Question titleTypeRequired
NameShort answerYes
EmailShort answerYes
ConsentCheckboxes, one optionNo

The single Consent option should read roughly: "Email me about events, early ticket access and member offers."

Confirmation message: "You're in. Show this screen to bar staff to claim your LVL 1 card."

Connect it: Responses tab → green Sheets icon → Select existing spreadsheet → Loyalty. Rename the new tab to exactly Signup responses.

Leave a placeholder in the form description for a privacy policy link — we're collecting names and emails for marketing, so it needs to be there before the form goes live. We'll send you the URL.

Step 4Activation form

This one sits behind the QR on every card back. New form, Activate Card. Two questions, again titled exactly:

Question titleTypeRequired
Card codeShort answerYes
Confirm your emailShort answerYes

Confirmation message: "Scan received. Show this screen to bar staff and roll the d20."

Connect it to the same spreadsheet, and rename the new tab to exactly Activation responses.

The card code field will be visible to members rather than hidden — Google Forms has no hidden fields. That's fine: the same code is printed on the card in their hand, and typing a different one gets them nowhere.

Step 5Get the prefill link

On Activate Card: ⋮ menu → Get pre-filled link. Type DUMMYCODE into the Card code box, leave the email blank, then Get link → Copy link.

You'll get something ending ?usp=pp_url&entry.123456789=DUMMYCODE.

This is the one thing everything else is waiting on

The QR codes can't be generated until this link exists, and the cards can't be printed until the QR codes exist. Send it over as soon as you have it — even if you haven't finished the rest.

Step 6The script

In the spreadsheet: Extensions → Apps Script. Delete whatever's in the editor and paste this in, then save.

Then the trigger — clock icon in the left sidebar → + Add Trigger:

Function to runonFormSubmit
Event sourceFrom spreadsheet
Event typeOn form submit

Pick the spreadsheet's trigger, not either form's own. The spreadsheet version is the one that can see which tab a response landed in, which is how the script tells the two forms apart.

Google will ask you to authorise, and will warn that the app isn't verified — normal for your own scripts. Advanced → Go to project → Allow.

Step 7Test it, then try to break it

  1. Submit the signup form with your own email. Check Members shows you at level 0.
  2. Copy any level 1 code from the Cards tab. Submit the activation form with that code and your email.
  3. Check three things: you're now level 1, that card row says activated and records your email, and the log shows activated.

Then the important half. Each of these should be refused, with a reason in the log, and should leave Members and Cards completely untouched:

Try thisExpected
Submit the same code againCard already activated
Submit a level 5 codeCannot skip levels
Submit a made-up codeNo such card code
Use an email that never signed upThey need to sign up first

When you're done, delete your test member row, set those test cards back to unissued, and clear the log.

What to send back

  • The prefilled activation link from step 5 — the blocker, send it first
  • The signup form's share link — needed for the table standees
  • Edit access to the spreadsheet
  • Confirmation the four refusal tests behaved

One other thing worth settling: whose Google account owns this. It shouldn't be a personal one belonging to someone who might move on.

If something misbehaves

SymptomCause
Nothing happens on submitTrigger isn't on, or it's the form's trigger rather than the spreadsheet's.
Every scan says "No such card code"The CSV wasn't imported, or was imported to the wrong tab.
Answers arrive blankA form question title doesn't match. Google identifies answers by title, so they have to agree exactly.
Log says activated but level didn't changeThe Level column is formatted as text, not Number.
Script error naming a column or tabSomething's spelled differently in the sheet than in the constants at the top of the script.
